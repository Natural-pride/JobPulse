# 路线图

## 当前状态

v0.9.0，2026-08-31 首次开源。

8 个状态、5 类 Action Items 规则、6 个页面、55 个后端测试、截图导入、漏斗/来源下钻——单人或小团队求职场景下的核心功能已经齐了。

## 已知限制

诚实清单，不藏：

### 数据 & 同步
- **没用户系统**：单用户，本机单 SQLite
- **没云同步**：换设备要手动复制 .db 文件
- **没导入导出**：没有 CSV / JSON 备份格式；想迁移只能直接拷贝 .db

### UI / UX
- **桌面优先**：手机上看列表会糊（响应式断点没做）
- **Action Items 不支持 snooze**：标记"暂时不跟进"得手动忽略
- **仪表盘不筛时间范围**：半年数据 vs 一个月数据混在一起
- **漏斗"Offer"桶在列表页只显示 `status=offered`**：accepted / declined / accepted_then_left 这 3 个状态需要手动选才能看到
- **截图导入依赖外部 LLM**：智谱 GLM-4V 挂了整个功能不可用
- **截图解析字段有限**：智谱 prompt 只能稳定识别 8-9 个字段（公司、岗位、时间、地点、薪资、联系人、来源、城市/区），不识别 JD 全文 / 福利

### 平台
- **Windows / macOS / Linux 都能开发**，但**没在 Linux 服务器上跑过长期服务**（本机 SQLite 文件锁的兼容性问题）
- **没 Docker 镜像**：要部署得自己 npm start 配 systemd / pm2

### 安全
- **后端无认证**：监听 0.0.0.0:3001 等于开放所有 API 访问
- **智谱 API key 在 .env**：千万别把 .env 提交到 git（`.gitignore` 已挡，但还要靠你自己）

## 短期（1-2 周）想做的

按优先级：

- [ ] **Action Items snooze**：点击"暂时不跟进"→ 7 天内不显示
- [ ] **仪表盘时间范围筛选**：7d / 30d / 90d / 全部，漏斗和热力图按区间计算
- [ ] **Round 0 = "已投简历"时间线事件**：从 `resume_submitted_at` 派生一条 timeline event
- [ ] **导出 Markdown 简历**：把通过的所有轮次整理成面试报告

## 中期（1-2 月）

- [ ] **来源转化率分析**：按 source 分组的漏斗（BOSS / 内推 / 拉勾 各自的投递→Offer 转化率）
- [ ] **沟通记录**：每条 opportunity 的 HR 沟通日志（日期、渠道、内容）
- [ ] **JD 链接解析**：粘贴拉勾/BOSS URL 自动 fetch + 解析
- [ ] **截图解析字段扩展**：加上福利、岗位要求、面试流程步骤

## 长期（不确定做不做）

评估中：

- 🤨 **AI 模拟面试**：基于 JD 和公司生成问题练习。**之前评估过，离"追踪"核心目标远，倾向不做**。如果做的话是独立功能，不影响主流程
- 🤨 **移动端原生应用**：工作量是 3-5 倍
- 🤨 **多用户 / 团队协作**：完全不同的产品形态，需要账号系统
- ❌ **浏览器扩展**：能自动从 BOSS 页面抓取信息，但违反 ToS，且偏离"本地工具"定位
- ❌ **AI 自动 Offer 谈判**：太离谱，不考虑
- ❌ **上云 / SaaS 化**：违背"数据属于用户"的核心定位

## 不做的东西

有些想法看起来"该有"，但评估后明确不做：

- ❌ **数据导入 / CSV 解析**：用户群太小，手工输入 2 分钟完事
- ❌ **邮件解析**：发邮件到 [email protected] 自动建 opportunity——部署 + 隐私成本太高
- ❌ **第三方登录**：本地工具加账号系统是 over-engineering
- ❌ **公开排行榜 / 社区功能**：违背隐私定位

## 决策原则

未来加功能用这三个标准筛：

1. **"是用户需要的还是开发者觉得酷的？"** 用户需要就做，开发者觉得酷就跳过
2. **"加这个会让产品更复杂还是更简单？"** 让产品更简单的做，更复杂的跳过
3. **"能不能在不破坏本地优先定位的前提下做？"** 不能就放弃

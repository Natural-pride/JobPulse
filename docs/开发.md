# 开发

本机从 0 到能跑起来。

## 环境要求

| 工具 | 版本 | 说明 |
|---|---|---|
| Node.js | 20+ | better-sqlite3 需要 Node 20 的 prebuilt binaries |
| npm | 10+ | 跟随 Node |
| 操作系统 | Windows / macOS / Linux | 都跑过 |
| 浏览器 | Chrome / Edge / Firefox | 任意现代浏览器 |
| Git | 任意 | 提交代码用 |

## 第一次拉代码

```bash
git clone https://github.com/Natural-pride/JobPulse.git
cd JobPulse
npm install            # workspaces 模式，根目录会装好前后端
```

## 启动开发环境

```bash
npm run dev:all        # 同时跑前后端（推荐）
```

等价于：

```bash
npm run dev:backend    # 仅后端 :3001
npm run dev:frontend   # 仅前端 :5173
```

打开 http://localhost:5173。

## 环境变量

复制模板：

```bash
cp backend/.env.example backend/.env
```

最小配置（截图导入需要）：

```env
ZHIPU_API_KEY=your_zhipu_key
```

完整配置见 [README §环境变量](../README.md#环境变量)。

## 跑测试

```bash
npm test                # 跑全部后端测试（55 个）
```

带监听模式（开发时推荐）：

```bash
cd backend
npx vitest --watch
```

新功能至少加 1 个测试。看 `backend/tests/` 现有 4 个测试文件的写法。

## 构建生产产物

```bash
npm run build           # 前后端都构建
# 产物：backend/dist/ + frontend/dist/
```

前端 `dist/` 是静态文件，可以直接用 nginx 托管。后端 `dist/` 是编译后的 JS，运行时还是需要 `node` 启动。

## 目录约定

### 后端
- 新增 API 端点 → `backend/src/routes/`
- 新增入参校验 → `backend/src/validate.ts`
- 新增类型 → `backend/src/types.ts`
- 工具/客户端 → `backend/src/lib/`
- 测试 → `backend/tests/`，文件名 `<feature>.test.ts`

### 前端
- 新增页面 → `frontend/src/pages/`
- 新增组件 → `frontend/src/components/` 或 `frontend/src/components/dashboard/`（仪表盘专用）
- 纯函数工具 → `frontend/src/lib/`
- 自定义 hooks → `frontend/src/hooks/`
- 共享类型 → `frontend/src/types.ts`

## 添加一个新功能的标准流程

举例：加一个"自定义轮次问题模板"功能

1. **后端先写**
   - 如果涉及新数据：在 `db.ts` 加列 + 加迁移
   - 如果涉及新端点：在 `routes/` 新建文件 + 在 `app.ts` 挂载
   - Zod schema 入参校验：放 `validate.ts`
   - 测试：在 `tests/` 新建 `xxx.test.ts`

2. **前端镜像类型**
   - 在 `frontend/src/types.ts` 加对应字段
   - 在 `api/client.ts` 加 API 封装

3. **前端 UI**
   - 在合适的页面 / 组件里使用
   - 遵循现有配色（参考 `lib/cardStyle.ts`、`lib/status.ts`）

4. **commit 规范**
   - 提交信息描述"为什么"而不是"改了什么"
   - 一个 commit 一个独立的逻辑改动
   - 后端 schema 变更和前端 UI 改动最好分开两个 commit

## 调试技巧

### 后端日志

`npm run dev:backend` 会输出所有 `console.log`，express 默认也打印每次请求的 method + path + status + 时长。要看 SQL，需要在 `db.ts` 加 `console.log` 临时调试（提交前删掉）。

### 前端网络请求

Chrome DevTools → Network 标签。FastAPI / Express 错误会显示 status 4xx/5xx，点开看 response body 就是 `{ error: "..." }`。

### 数据库直接看

```bash
# 安装 sqlite3 CLI（macOS 自带，Windows 单独装）
sqlite3 backend/data/jobpulse.db

# 查所有机会
SELECT id, company_name, status, created_at FROM opportunities;

# 查等待回复超 5 天的
SELECT * FROM opportunities
WHERE status = 'awaiting_response'
  AND julianday('now') - julianday(resume_submitted_at) > 5;
```

### 重置数据库

开发时如果数据乱了想从 0 开始：

```bash
# 停服务，删文件，重启会自动重建
rm backend/data/jobpulse.db
npm run dev:all
```

## 常见坑

| 现象 | 原因 | 解决 |
|---|---|---|
| 启动后 5173 空白页 | 后端没起，API 请求失败 | 先 `npm run dev:backend` 看 3001 是否有响应 |
| 截图导入 502 | `ZHIPU_API_KEY` 没配 / 失效 / 没余额 | 检查 `backend/.env` |
| 端口被占用 | 5173 / 3001 已有进程 | `lsof -i:5173` 找进程 kill；Windows 用 `netstat -ano` 找 PID |
| 改了 db.ts schema 但老库不生效 | 迁移没触发 | 看 `db.ts` 的 `PRAGMA table_info` 检查逻辑 |
| Vite HMR 不刷新 | TS 类型错误 | 看终端报的错；硬刷新 Ctrl+Shift+R |
| 提交时把 `.env` 误提交 | .gitignore 漏了 | `git rm --cached backend/.env` + 提交 |

## 性能注意事项

- 列表分页默认 10 条，不要改成 100+（前端渲染开销大）
- 详情页一次性 fetch 所有 rounds，没分页（通常 < 10 条，OK）
- 仪表盘最近活动写死取 4 条（`frontend/src/lib/dashboardUtils.ts`）
- SQLite 配 `journal_mode = WAL`（已在 `db.ts` 启用），并发读不互斥

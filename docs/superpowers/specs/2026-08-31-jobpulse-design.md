# JobPulse 设计文档

> 个人面试进度追踪工具 — 设计稿
> 日期：2026-08-31
> 作者：MuGui

## 目标

为正在求职中的 MuGui 打造一个**本地运行、单人使用**的面试进度追踪工具，解决"手里同时推进多家公司面试，状态记不住、JD/福利信息散落、面试完的感受和细节容易忘"的问题。

## 1. 技术栈

| 层级 | 选型 | 说明 |
|---|---|---|
| 前端框架 | Vite + React + TypeScript | 启动快、生态成熟、TS 守字段类型 |
| 路由 | React Router | 多页面导航 |
| 样式 | Tailwind CSS + shadcn/ui | 组件库 + 原子化样式 |
| 数据存储 | SQLite（`better-sqlite3`） | 单文件 `data/jobpulse.db`，便于备份 |
| 后端 | Express（一个文件足够） | 给前端暴露 REST API |
| 启动 | `npm run dev:all` 起前后端 | 浏览器访问 `http://localhost:5173` |

**架构**：

```
浏览器 (React)  ─HTTP─►  Express 服务 (Node.js)  ─SQL─►  SQLite 文件
```

**为什么不用纯前端 + IndexedDB / localStorage**：JD/笔记等长文本可能很大，localStorage 5MB 限制很快爆；SQLite 文件可以一键备份/迁移到新电脑。

## 2. 数据模型

两张表，通过 `opportunity_id` 关联。

### 表 1：`opportunities`（面试机会，每家公司/岗位一条）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | int PK | 自增 |
| `company_name` | text NOT NULL | 公司名称 |
| `position_name` | text NOT NULL | 岗位名称 |
| `city` | text | 城市（如"杭州"） |
| `address` | text | 详细地点（线下时填） |
| `salary_range` | text | 薪资范围，格式如 `10K-12K*13` |
| `benefits` | text | 福利待遇（自由文本或标签） |
| `has_weekends_off` | bool | 是否双休 |
| `work_hours` | text | 上下班时间，格式如 `9:00-18:00` |
| `jd_text` | text | 岗位 JD 长文本 |
| `jd_url` | text | JD 链接 |
| `source` | text | 来源（Boss/拉勾/内推/猎头） |
| `contact_info` | text | 联系方式 |
| `status` | enum NOT NULL | 见下方枚举 |
| `final_salary` | text | 最终谈下薪资，格式如 `11K*13` |
| `final_benefits` | text | 最终福利 |
| `notes` | text | 综合备注 |
| `created_at` | datetime | |
| `updated_at` | datetime | |

**`status` 枚举**：
- `in_progress` — 进行中
- `offered` — 已 Offer
- `accepted` — 已接受
- `rejected` — 已被拒
- `withdrawn` — 我已撤回

### 表 2：`interview_rounds`（面试轮次，每个机会下多条）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | int PK | 自增 |
| `opportunity_id` | int NOT NULL FK→opportunities.id | |
| `round_number` | int | 第几轮（1、2、3...） |
| `round_type` | enum | HR筛选 / 技术一面 / 技术二面 / 综合面 / 终面 / 谈薪 / 其他 |
| `format` | enum | 线上视频 / 线下 / 电话 |
| `location` | text | 面试地点（线下时填） |
| `scheduled_at` | datetime | 计划面试时间 |
| `actual_at` | datetime | 实际面试时间（面完后回填） |
| `duration_minutes` | int | 实际面试时长 |
| `questions` | text | 问了哪些问题 |
| `my_performance` | text | 我的表现感受 |
| `outcome` | enum | 待面试 / 已通过 / 未通过 / 已取消 |
| `next_round_date` | datetime | 下一轮时间 |
| `notes` | text | 备注 |
| `created_at` | datetime | |
| `updated_at` | datetime | |

**关键设计点**：
- **进度不存字段**：当前轮次/状态由 `opportunity.status` + `interview_rounds` 派生计算，不冗余存储。
- **`salary_range` / `work_hours` / `final_salary` 用文本**：用户按习惯格式手填（如 `10K-12K*13`、`9:00-18:00`），不拆成数字字段。
- **JD 单独存长文本字段**：避免和其他短字段挤在一起。

**分组折叠**——15+ 字段分 5 组，默认折叠非首组，避免"一打开就被一堆字段淹没"。

3. **工作时间**：上下班时间、是否双休
4. **岗位 JD**：JD 长文本
5. **联系信息**：来源、联系方式、备注

## 4. 核心用户流程

```
1. 创建机会（新建表单）
   ↓
2. 自动跳转到详情页
   ↓
3. 添加第一轮面试（邀约时填上半段）
   ↓
4. 面试当天/后面完
   ↓
5. 回填该轮下半段（实际时间/问题/表现/结果）
   ↓
   ┌──────────┬──────────┬──────────┐
   ↓          ↓          ↓          ↓
  通过       未通过       Offer      取消
   ↓          ↓          ↓
6a. 添加    6b. 标记     6c. 填
   下一轮    机会状态     final_salary
   ↓         为"已拒"     + final_benefits
7a. 回到     ↓             ↓
   步骤 4    流程结束    7c. 标记
   循环                    为"已接受"
                            ↓
                          流程结束
```

### 关键交互

- **轮次两段填写**：邀约时填上半段（必填），面完后填下半段（可后补），允许先存后补。
- **状态快捷方式**：
  - 某轮点"标记为已通过" → 自动追加一个"下一轮"草稿
  - 某轮点"标记为未通过" → 弹窗问"是否同时把机会标记为已拒？"
- **状态派生统计**（不存数据库，只读计算）：
  - 进行中 + 任意轮"待面试" → 仪表盘"即将到来"显示
  - `status = offered/accepted` → 仪表盘"Offer"统计 +1
  - 所有轮次为"未通过/已取消" → 仪表盘"被拒"统计 +1

### 删改边界

- **删机会**：弹窗确认（"将同时删除 N 轮面试记录"）
- **删单轮**：不需要二次确认
- **改状态**：自由改，不锁死
- **改机会字段**：复用新建表单

## 5. 范围边界

### v1 必做

✓ 5 个页面（仪表盘/列表/新建编辑/详情/轮次 Modal）  
✓ 两张表 + 完整 CRUD  
✓ 状态管理与状态切换快捷方式  
✓ Dashboard 4 个统计 + 即将到来列表  
✓ 详情页时间轴 + 4 卡片概览  
✓ 表单 5 分组折叠  
✓ 轮次两段填写  
✓ 删/改/查的基本操作  
✓ 本地 SQLite 存储 + `npm run dev` 跑起来  

### v1 明确不做

✗ 多用户/登录  
✗ 云同步/账号系统  
✗ 邮件解析/招聘网站自动抓取  
✗ AI 简历打分/岗位匹配  
✗ 浏览器插件  
✗ 移动端 App / PWA 离线（响应式有，不做应用）  
✗ 设置页面  
✗ 主题切换（深色模式）  
✗ 多语言（仅中文）  
✗ 数据导入  
✗ 面试提醒/系统通知  
✗ 统计图表/分析（仅 4 个数字）  

### 未来扩展

| 优先级 | 功能 | 解决痛点 |
|---|---|---|
| 高 | 导出 JSON/CSV | 换电脑/分析 |
| 高 | 浏览器原生 Notification 提醒 | 提前 1 小时弹通知 |
| 中 | Offer 对比视图 | 多 Offer 横比 |
| 中 | Dashboard 漏斗/按月图表 | 复盘求职节奏 |
| 低 | 标签/分类 | 按行业/技术栈分组 |
| 低 | JD 全文搜索 | 回忆某技术栈的公司 |
| 低 | 深色模式 | 护眼 |
| 低 | PWA / 多设备同步 | 平板/手机用 |

**扩展判断标准**：v1 跑 2 周后，**你实际哪里卡/哪里不爽**，那个就是 v1.1 要解决的。

## 6. 风险与兜底

| 风险 | 后果 | 兜底 |
|---|---|---|
| `.db` 文件损坏 | 数据丢 | 手动复制 `data/jobpulse.db` 做备份；v1.1 加一键导出 |
| 换电脑 | 数据带不走 | v1 手动拷；v1.1 加导出 |
| 浏览器关了服务没关 | 端口占用 | `npm run dev:stop` 脚本 |
| 字段以后想加 | 老数据缺字段 | `migrations/` 管理表结构 |
| 想给朋友用 | 单机单用户不支持 | 改大改小，不是 v1 的事 |

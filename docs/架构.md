# 架构

## 总览

本地优先的单体 Web 应用，三层：浏览器 → Vite/React 前端 → Express 后端 → SQLite 文件。

```
┌──────────────┐   HTTP/JSON   ┌──────────────┐   better-sqlite3   ┌──────────────┐
│   Browser    │◀────────────▶│   Express    │◀────────────────▶│   SQLite     │
│  React 19    │               │   Node 20    │                   │  .db 文件    │
│  Vite + TS   │               │  + Zod       │                   │  (单文件)    │
└──────────────┘               └──────────────┘                   └──────────────┘
       ▲                              ▲
       │ 智谱 GLM-4V API（仅截图导入用）      │
       │ ZHIPU_API_KEY from .env       │
       └──────────────────────────────┘
```

端口：
- 前端 dev server：`5173`
- 后端 API：`3001`

## 技术栈

| 层 | 用的 |
|---|---|
| 前端 | React 19 + Vite + TypeScript + Tailwind CSS v3 |
| 后端 | Express 4 + better-sqlite3 + Zod |
| 截图 OCR | 智谱 GLM-4V（OpenAI 兼容 API） |
| 数据库 | SQLite 3.49+（用到了 `DROP COLUMN`） |
| 测试 | Vitest（55 个后端用例） |
| 状态字段 | 8 个：in_progress / awaiting_response / offered / accepted / rejected / withdrawn / declined / accepted_then_left |

## 后端模块

```
backend/src/
├── db.ts                # SQLite 初始化 + 一次性 schema 迁移
├── types.ts             # 共享 TS 类型（OpportunityStatus / RoundType / ...）
├── validate.ts          # 所有入参的 Zod schemas
├── app.ts               # Express 装配（中间件、路由挂载）
├── server.ts            # 启动入口（监听 PORT）
├── routes/
│   ├── opportunities.ts # 6 个端点：list / listPaged / get / create / update / delete
│   ├── rounds.ts        # 4 个端点：list / create / update / delete
│   ├── parse.ts         # 1 个端点：POST /api/parse-screenshot（截图上传 + 智谱）
│   └── actionItems.ts   # 1 个端点：GET /api/action-items（5 条规则的纯函数）
└── lib/
    └── zhipu.ts         # 智谱 GLM-4V 客户端封装
```

**核心模式**：

- `db.ts` 的 `initDb(path)` 是数据库访问的唯一入口
  - 在 `getDb()` 中根据 `process.env.DB_PATH` 决定路径
  - 默认值锚到源文件位置（`fileURLToPath(import.meta.url)`），不依赖 `cwd`
- `routes/*.ts` 每个文件 `export function createXxxRouter(db)`，由 `app.ts` 装配
- `actionItems.ts` 的 `computeActionItems(opps, rounds, now)` 是**纯函数**，方便测试
- 所有入参在路由层先过 `*.safeParse()`，失败返回 400

**核心模式**：

- 所有路由参数在 `App.tsx` 一处声明；页面用 `useParams` / `useSearchParams` 读
- 列表筛选完全 URL 化：仪表盘点击漏斗条 → `/opportunities?funnel=interviewed` → `OpportunityList` 读 URL 调 API
- 类型在 `frontend/src/types.ts` 镜像后端 `backend/src/types.ts`，**手动同步**（没有 codegen）

## 数据流：典型一次"打开列表"

```
User 点击 "Opportunities" 
  → React Router 导航到 /opportunities
  → OpportunityList 读 URL ?page=1 ?status=in_progress
  → useEffect 触发 → api.opportunities.listPaged({ page, pageSize, status })
  → fetch GET /api/opportunities?page=1&pageSize=10&status=in_progress
  → Express 路由：listQuerySchema.safeParse → db.prepare('SELECT ...').all()
  → 返回 { items, total, page, pageSize, hasMore }
  → 对每个 item 再 fetch /api/opportunities/:id/rounds 拿轮次
  → 渲染 OpportunityCard 列表
```

## 数据流：截图导入

```
User 截图后 Ctrl+V
  → OpportunityImport 的 useEffect 监听 document 'paste'
  → 提取 clipboardData.items[].getAsFile()
  → 包成 File 对象 → setFile → 渲染预览图
User 点 "开始解析"
  → fetch POST /api/parse-screenshot (multipart/form-data)
  → multer.memoryStorage 接收（不上磁盘）
  → routes/parse.ts: 调智谱 GLM-4V
  → 智谱返回 JSON → Zod 解析 → 字段映射到前端表单
  → 返回 ParsedInterview
  → 前端填表 → 用户编辑 → 点保存
  → POST /api/opportunities → POST /api/opportunities/:id/rounds
  → 跳转 /opportunities/:id
```

## 关键设计决策

### 1. 数据属于用户：单文件 SQLite
- 整个应用的状态 = `backend/data/jobpulse.db` 一个文件
- 备份：停止服务，`cp .db ~/backups/`
- 换机器：把文件复制到新机器的同一位置，重启即用
- 不支持云同步（也不打算做）

### 2. DB 路径锚到源文件
- `getDb()` 默认值用 `fileURLToPath(import.meta.url)` 解析
- 不依赖 `process.cwd()`，避免从别的目录启动 `npm run dev` 时创出野生的空 DB

### 3. 截图不持久化
- multer 用 `memoryStorage`，图片在请求结束后被 GC
- DB 里只存解析后的结构化字段（公司名、岗位、时间），不存 base64

### 4. 状态字段用 8 个，覆盖中文招聘流程
- `awaiting_response`（等待回复）：BOSS 聊完投简历、HR 说"等回音"
- `declined`（拒 offer）：拿到 offer 后主动拒绝
- `accepted_then_left`（入职后离职）：干了一阵又跳
- 8 个状态见 `backend/src/types.ts`

### 5. 列表筛选 URL 化
- 仪表盘的漏斗条 / 来源条都是 `<Link>`，跳到 `/opportunities?funnel=interviewed` 等
- 列表页 `useSearchParams` 解析 → `api.opportunities.listPaged()` 直接传
- 用户可以分享筛选好的 URL

### 6. 类型手动同步
- 后端 `backend/src/types.ts` 和前端 `frontend/src/types.ts` 字段一致
- 没有 codegen（项目小，手动改成本更低；改 schema 时两处都改）

### 7. Action Items 是纯函数
- `computeActionItems(opps, roundsByOpp, now)` 不依赖时间、不读 DB
- 测试时直接构造 Opportunity 数组和 round 数组传进去
- 5 条规则集中在 `backend/src/routes/actionItems.ts` 一个文件
